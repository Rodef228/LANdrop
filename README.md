# Mesh-CU Messenger

**Mesh-CU** — это децентрализованный P2P-мессенджер для локальной сети (LAN) с поддержкой обмена файлами через mini-torrent. Никаких серверов, никакого интернета — только прямое соединение между узлами.

---

## Как это устроено

### Обнаружение узлов (Discovery)

Каждый узел каждые 2 секунды отправляет UDP-broadcast на порт **9999** с сообщением вида:

```
CU-BRIDGE-HELLO:{nickname}:{TCP_порт}
```

Где `nickname` — имя пользователя (флаг `-name`), а `TCP_порт` — порт TCP-сервера этого узла.

Все узлы в сети слушают порт 9999. Когда приходит broadcast от нового узла — он добавляется в реестр активных пиров.

Благодаря `SO_REUSEADDR` несколько узлов на одной машине могут одновременно слушать порт 9999.

### Сеть (TCP)

Для передачи данных (чат, файлы) используется TCP. Каждый узел запускает TCP-сервер на динамическом порту (ОС назначает сама, если не указан конкретный). Реальный порт передаётся через broadcast, поэтому другие узлы знают, куда подключаться.

### Файловое хранилище (CDN)

Файлы делятся на чанки по **64 КБ** и хранятся в директории `./storage/`. Каждый чанк — отдельный файл на диске.

**Как работает обмен файлами:**

1. **Анонс** — узел объявляет, что у него есть файл, и рассылает список чанков, которыми владеет
2. **Запрос** — другой узел запрашивает конкретные чанки у конкретных владельцев
3. **Скачивание** — все чанки запрашиваются параллельно, каждый у своего владельца
4. **Ре-анонс** — после завершения скачивания узел рассылает обновлённый список своих чанков

### Коллизия имён

Если два узла запущены с одинаковым именем (`-name`), второй узел получит критическую ошибку и завершится. Нужно перезапустить с другим именем.

## Запуск

```bash
go run ./cmd/node/main.go
```

### Флаги

| Флаг | Описание | По умолчанию |
|------|----------|-------------|
| `-name` | Имя пользователя в сети | `node-{hostname}-{PID}` |
| `-port` | TCP-порт для соединений | 0 (динамический, назначается ОС) |
| `-storage` | Директория для хранения файлов | `./storage` |

### Примеры

```bash
# Запуск с именем
go run ./cmd/node/main.go -name alice

# Запуск с конкретным портом
go run ./cmd/node/main.go -name bob -port 9000

# Запуск с кастомной папкой хранения
go run ./cmd/node/main.go -name charlie -storage ./my_files
```

## Команды

### Чат

Просто введите текст и нажмите Enter — сообщение уйдёт всем активным узлам в сети.

```
you: Всем привет!
```

### `/announce <путь_к_файлу> [id]`

Анонсировать файл для раздачи. Файл будет порезан на чанки и доступен для скачивания другим узлам.

```
/announce ./myphoto.jpg
/announce ./document.pdf my_custom_id
```

### `/download <id_файла>`

Скачать файл по его ID. Все чанки запрашиваются параллельно у тех узлов, у которых они есть.

```
/download a1b2c3
```

## Структура проекта

```
cmd/node/main.go              — точка входа, CLI, обработка сообщений
internal/discovery/           — обнаружение узлов (UDP broadcast)
  discovery.go                — сервис обнаружения (listen + broadcast)
  registry.go                 — реестр активных пиров с очисткой по таймауту
internal/network/server.go    — TCP-сервер для передачи данных
internal/protocol/types.go    — типы сообщений, кодирование/декодирование
internal/cdn/                 — файловое хранилище (Content Delivery Network)
  cdn_manager.go              — управление файлами, чанками, владельцами
  file_manager.go             — чтение/запись чанков на диск
```

## Как это работает (подробно)

1. Узел запускается, поднимает TCP-сервер на случайном порту
2. Запускается UDP-broadcast: каждые 2 секунды узел сообщает о себе
3. Другие узлы в сети получают broadcast и добавляют новый узел в реестр
4. При вводе текста — сообщение уходит всем активным пирам по TCP
5. При `/announce` — файл режется на чанки, сохраняется в storage, рассылается анонс
6. При `/download` — запрашиваются все чанки параллельно у владельцев
7. После скачивания — ре-анонс, чтобы другие знали, что теперь чанки есть и у этого узла
8. Если узел не отвечает 30+ секунд — он удаляется из реестра
